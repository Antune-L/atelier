# Autonomous original-source coverage

An autonomous plan now preserves its original title, description and PRD in the existing autonomous ticket state. It also records SHA-256 digests for referenced repository files. This snapshot is captured when the initial autonomous plan is frozen, before implementation.

Use relative repository paths for authoritative source documents. Local Markdown links, absolute document/image paths, Markdown images and Figma links are discovered from the description and PRD. External Markdown links labelled `source`, `spec`, `prd`, `mockup` or `maquette` are authoritative sources; unrelated documentation URLs remain context. Import authoritative external source content into the repository before starting. A URL alone does not preserve its original contents or revision.

The existing full quality run first starts an independent read-only requirements inventory session with only the original sources and images, without the implementation plan or extracted criteria. Source excerpts are attributed to its actual reads or attached image identities, and a retained artifact assigns a stable digest ID to every obligation. A second fresh-context read-only source auditor inspects the actual isolated candidate and independently re-reads the original sources. It must assess every inventory ID exactly once, preserving the original obligation, and add any further omissions it discovers. Missing, duplicate or unknown IDs cannot pass. Each reported obligation needs an exact original-source excerpt, at least one real frozen criterion ID, and an implementation citation attributed to an actual completed read. An original obligation absent from the frozen criteria blocks completion and requires explicit reconciliation rather than a phantom criterion ID. Every nonempty text source and every referenced file must be represented. Claude native reads and Codex single-file command observations use the same citation attribution helper as independent test-relevance analysis.

The source auditor also independently evaluates each lot's technical/functional validation applicability against its scope and the original sources.

The final browser validator receives the same digest-checked original raster mockups. It must compare every original with the actual rendered candidate and cite a retained viewport or element screenshot produced after navigation in that run. Missing, duplicate or unrecognised image identities and absent screenshots cannot certify fidelity; a screenshot-attributed deviation enters the existing bounded correction loop.

The audit artifact and existing action journal retain its session identity and observations. The ticket retains the accepted/correctable result, run ID, candidate revision, source/configuration/snapshot fingerprints and artifact path. Delivery requires accepted coverage from the same full run as the final technical and acceptance checks. A new candidate requires a new full run and audit; changing frozen text or referenced file contents cannot silently replace the approved scope.

An independently observed missing obligation can enter the existing bounded correction loop. Inconclusive observations, absent original snapshots and unreadable or changed sources prevent completion. Existing start, correction and deadline allowances still apply. Restarting an interrupted run does not reuse an unaccepted audit. A successful audit alone never replaces technical checks, browser scenarios, cleanup or independent final review.

## Qualification boundaries

The current source auditor qualifies repository text and up to five PNG, JPEG, GIF or WebP mockups (two megabytes each). The backend attaches the exact digest-checked image bytes through the existing native image transport for both providers and records their identities in the audit artifact. This establishes which original image the independent auditor received; it does not independently prove the model interpreted it correctly. SVG and PDF sources fail closed because this path has no supported native attachment contract for those formats. External Figma or other source URLs also fail closed until imported as a supported immutable source. A textual description or green command output does not certify fidelity to an unavailable mockup. This is an explicit incomplete qualification, not a production or provider validation claim.

Historical autonomous plans without the captured original snapshot cannot acquire full-delivery approval from old criterion evidence. They retain their work and require an explicit source/scope reconciliation rather than silently backfilling an original snapshot from already modified sources. There is no automatic scope expansion or source-replacement API in this change.

The Orchestrateur integration continues to use the existing autonomous-ticket and delivery settings. Its input contract is to include the complete approved source text or supported repository source references before initial plan submission. No new cross-repository engine or campaign requirement is introduced.
